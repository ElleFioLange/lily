i want there to be plugins

the plugins define a manifest with metadata
the metadata is a unique string id,
a name for the plugin
the type of surface it defines (audio or visual)

the plugin should define a typescript type with the config schema for keywords to define to send control signals to it

the plugin should define an initialization script

for something like hydra or strudel, this script should spawn an instance within the web environment of Lily

for something like ableton or touch designer this script should send a ping to the application to verify that it is active and listening for control signals

the initialization script is also where a plugin would instantiate a local state store if it needs one

plugins should define a main handler script

this script takes the Lily input (calling it poiesis) and the current configuration file (as a json object) and handles parsing, generating the control signals, and sending the signals
the script should use a control signal structure, even in the case of something like hydra or strudel. hydra currently works by taking the parsed input and then appending variable values to the beginning of the hydra shader before refreshing the render calling
the plugin should instantiate a state store which contains the hydra shader code as well as a listener which handles control signals that update the state of the peripheral values controlled by the poiesis

need to implement piping for visual and audio signals to handle reactivity effects, text shaders, and previews

hydra needs a cue/setup structure thing

video plugins need to define a component that will hold the video stream
when one of these plugins is active, that component will be loaded into both the preview window and the performance window and will be alpha mixed according to the mixer settings

plugins have access to some helper functions from within Lily
such as:
sending OSC messages over UDP
file loading and saving

preload needs a pluginListenerRegistry that plugins can add listeners to

main editor window has the currently selected plugin's "Main" component loaded. tabbing to a new plugin unmounts the old Main component and mounts the new one.
state continuity is handled through a zustand store that is created and managed by the initialization script of the plugin
this is run within useEffect hook within the top level app component.
this way the "Main" editor components can be loaded and unloaded without disrupting state continuity

The main editor window has a button to switch to "Live preview", which sets it to display the a mirror of the performance window.
this is a read-only mode, but mouse interactivity is allowed for the currently selected plugin (scrolling text or mouse position updates in hydra, etc.)
this mode loads the "Render" components of any active plugins that have a render component
touch designer would have a "graphics" renderer,
strudel would have a "code" renderer
hydra would have two renderers, one for "graphics" and one for "code"
these are alpha mixed according to the mixer params in the settings panel

plugins can also define "effects" renderers
these can take other renderer layers as inputs, or target other renderer layers as outputs.
example: ableton plugin provides a renderer layer that generates audio reactive text effects for the poiesis renderer, takes the poiesis layer as an input and also targets the poiesis layer as the layer it draws the effect on top of
these effects also have corresponding mixer sliders in the settings panel
